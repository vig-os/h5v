# [PR 20](https://github.com/vig-os/h5v/pull/20) chore: advance the devkit flake pin with devkit upgrades

The automated devkit upgrade has been failing since 2026-10-05 (1.17.0 → 1.18.0; see the open upgrade-failure issue #15).

flake.nix pins `vigos.url` to the devkit release (`?ref=1.17.0`). By default the upgrade does not advance that pin. So the upgrade commit runs devkit 1.18's new hooks (`validate-branch-name`) inside the 1.17 shell, and they fail to spawn. CI would also reject a pin that differs from `DEVKIT_VERSION`.

This sets `DEVKIT_FLAKE_PIN_ADVANCE=true`, which devkit 1.18.0 honors. The next devkit-upgrade run then bumps the pin and `flake.lock` together with the scaffold. Upstream fix: vig-os/devkit#1856, which makes this the default for lockstep pins.

After merge: re-run the Devkit Upgrade workflow.
